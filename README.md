# Adrobot · обёртка над Keitaro

Создание кампаний и редактирование офферов через **FastAPI + SQLAlchemy**. Интерфейс — HTML/CSS и JavaScript без сборки и внешних UI-зависимостей.

## Возможности

- Кампания с выбранными доменом, группой и источником из API Keitaro.
- Два последовательных потока: заданная страна → Google, остальные посетители → выбранный оффер.
- Загрузка существующей кампании по ID и обновление из Keitaro.
- Добавление, удаление из потока и восстановление офферов. Глобальные офферы не удаляются.
- Целочисленные доли с суммой 100%, закрепление долей, перераспределение остатка после изменений.
- Удалённые привязки и закреплённые доли сохраняются в SQLite через SQLAlchemy.
- Защита от устаревшего состояния интерфейса и обнаружение изменений потоков вне приложения.
- Отдельный запрос статистики за текущий день UTC. Ошибка отчёта не подменяется нулевыми данными.
- Постоянный локальный деморежим с пятью офферами для проверки без аккаунта Keitaro.

## Требования и установка

Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Доступ к интернету нужен только для установки зависимостей и работы с реальным Keitaro. Точные версии зависимостей зафиксированы в `uv.lock`.

```sh
git clone https://github.com/SDeeKey/adrobot-keitaro-wrapper.git
cd adrobot-keitaro-wrapper
uv sync --frozen
```

Создайте `.env` на основе `.env.example`:

```powershell
# PowerShell
Copy-Item .env.example .env
```

```sh
# Linux / macOS
cp .env.example .env
```

## Миграции и запуск

Из корневой папки проекта:

```sh
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Интерфейс: http://127.0.0.1:8000. OpenAPI/Swagger: http://127.0.0.1:8000/docs.

Миграция создаёт новую локальную базу `adrobot.db`, таблицы `campaigns`, `demo_state` и таблицу версии Alembic. База и `.env` не входят в Git.

Проверить текущую ревизию:

```sh
uv run alembic current
```

По умолчанию `DEMO_MODE=true`: приложение полностью локальное, не создаёт кампании в трекере и хранит демоданные между перезапусками. Создайте кампанию, добавьте несколько офферов, измените долю, закрепите её и удалите/восстановите другой оффер. При удалении последнего активного оффера операция отклоняется.

## Подключение Keitaro

Укажите в локальном `.env`:

```dotenv
DEMO_MODE=false
KEITARO_URL=https://your-tracker.example.com
KEITARO_API_KEY=your-api-key
CAMPAIGN_PREFIX=test_shmelev_
DATABASE_URL=sqlite:///./adrobot.db
```

`KEITARO_URL` — адрес **без** `/admin`. API-ключ берётся из админки трекера. Нужны права на чтение доменов, групп кампаний, источников, офферов и отчётов, создание/редактирование кампаний и потоков. API-ключ передаётся в заголовке `Api-Key` только backend-клиентом; браузер его не получает. Пароль от админки приложению не нужен.

Перезапустите приложение после изменения `.env`. В интерфейсе режим будет обозначен `KEITARO · LIVE`.

Все новые кампании получают префикс `test_shmelev_`; редактор разрешает изменять только кампании с этим префиксом. Это защита общих тестовых данных, а не механизм пользовательской авторизации.

## Как устроено создание кампании

1. Проверяются входные данные: название, ISO-код страны и доступность выбранных объектов.
2. `POST /campaigns`: создаётся приостановленная кампания с ротацией по позиции и уникальным alias.
3. `POST /streams`: первый поток с фильтром `country / accept` и HTTP-редиректом на Google.
4. `POST /streams`: второй поток без фильтров с выбранным оффером и долей 100%.
5. `PUT /campaigns/{id}`: кампания активируется после успешного создания обоих потоков.
6. Кампания и потоки перечитываются через API, снимок сохраняется локально.

При ошибке настройки известный ID частично созданной кампании возвращается в сообщении. Автоматического удаления и повторной отправки нет: это предотвращает удаление чужих данных и скрытое создание дубликатов. При сетевом тайм-ауте результат запроса может быть неизвестен — перед повтором нужно проверить Keitaro.

## Логика долей

Алгоритм в `app/shares.py` не зависит от API и базы:

1. Сохраняет закреплённые целые доли.
2. Делит оставшийся процент поровну между незакреплёнными активными офферами.
3. Остаток от деления выдаёт первым офферам в порядке списка: например, 34/33/33.
4. Удалённые привязки получают 0% и не участвуют в распределении.

Изменение процента закрепляет его. Сумма закреплённых долей больше 100%, удаление последнего активного оффера или невозможное распределение отклоняются до запроса к трекеру. Если все доли закреплены, их сумма должна быть ровно 100%. Для добавления оффера при полностью занятом закреплённом трафике сначала открепите или уменьшите одну из долей.

Изменения отправляются сразу. В Keitaro записывается полный список активных привязок конкретного потока через `PUT /streams/{id}`; остальные настройки потока не переписываются. После записи приложение перечитывает поток и проверяет сохранённые доли.

## Проверки

```sh
uv run pytest -q
```

Тесты не обращаются к реальному трекеру. Используются временные SQLite-базы, реальные миграции, FastAPI TestClient, демоклиент и HTTPX MockTransport. Проверяются создание двух потоков, фильтр страны, связанные справочники, суммы долей, закрепление, удаление/восстановление, сохранность метаданных после перезапуска, конфликты версий, ошибки API и отсутствие ключа в ответах.

Ручной сценарий:

1. Создать кампанию с DE и первым оффером.
2. Убедиться, что поток страны направлен на Google, а второй имеет один оффер с 100%.
3. Добавить второй оффер → 50/50.
4. Изменить долю первого на 70 → 70/30, первая доля закреплена.
5. Добавить третий оффер → 70/15/15.
6. Удалить второй → 70/30. Включить показ удалённых и восстановить → снова сумма 100%.
7. Перезапустить приложение, обновить кампанию, проверить закрепление и историю удалённых привязок.
8. В LIVE-режиме сверить потоки и проценты в админке Keitaro.

## Структура

```text
app/
  main.py       FastAPI, маршруты, same-origin защита
  config.py     переменные окружения
  db.py         SQLAlchemy-модели и сессии
  keitaro.py    HTTP-клиент и постоянный деморежим
  service.py    бизнес-операции и синхронизация
  shares.py     распределение процентов
  schemas.py    валидация запросов
  static/       интерфейс
migrations/     Alembic
tests/          автоматические проверки
```

## Ограничения

- Приложение предназначено для локального запуска на `127.0.0.1` одним процессом Uvicorn. Между изменениями в одном процессе используется блокировка. Для нескольких воркеров нужны распределённая блокировка и полноценная авторизация.
- Ревизия снимка защищает от устаревшей вкладки, сравнение потоков — от уже произошедшего внешнего изменения. Keitaro не предоставляет общей транзакции с локальной БД или compare-and-swap для потока: внешнее изменение строго между проверкой и записью полностью исключить нельзя.
- Режимы LIVE и DEMO используют одну схему данных; для независимых окружений задайте разные `DATABASE_URL`.
- Статистика запрашивается отдельно и зависит от прав API. Графики трендов из видео не реализованы: основная часть редактора — офферы, их состояние и доли.
- На момент подготовки выданный тестовый аккаунт отвечает `Incorrect password`; проверка на этом трекере не выполнена. HTTP-клиент подготовлен по официальной документации, совместимость с конкретной версией сервера нужно подтвердить при рабочем доступе.

Документация API: https://admin-api.docs.keitaro.io/ и https://docs.keitaro.io/en/development/admin-api.html.
